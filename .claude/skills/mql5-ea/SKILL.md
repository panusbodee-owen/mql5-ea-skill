# MQL5 EA (book-grounded, token-efficient)

## Token rules
1. New EA → run `scripts/scaffold_ea.py`, then edit only the strategy functions (`EntrySignal`, `ExitSignal`, inputs). Never hand-write the risk/execution core.
2. Existing code → run `scripts/check_mq5.py` first; fix reported lines; show diffs only.
3. Results → run `scripts/analyze_trades.py` on the exported trades; never compute metrics in chat.
4. Load one reference at a time: `ea-patterns.md` (API/how), `strategies.md` (which archetype), `risk-and-testing.md` (sizing/validation), `books.md` (only when asked for sources).

## Scripts (run, do not read)
```bash
S=.claude/skills/mql5-ea/scripts   # or ~/.claude/skills/mql5-ea/scripts
python3 $S/scaffold_ea.py MyTrend --strategy ma_cross|donchian|bb_reversion|session_breakout [--magic 240001] --out MQL5/Experts
python3 $S/check_mq5.py MQL5/Experts/MyTrend.mq5
python3 $S/analyze_trades.py trades.csv --initial 10000 --risk 100 [--xlsx report.xlsx]
```

## Non-negotiables in every EA
- Stop loss on every order; size from risk % and stop distance; round volume down; skip if below min lot.
- Indicator handles in `OnInit`, `CopyBuffer` with checked counts, `IndicatorRelease` in `OnDeinit`.
- Decide on closed bars once per bar; manage stops per tick.
- Magic number filter on every position loop; check `ResultRetcode()`; margin check before sending.
- No martingale, no unbounded grid, no averaging down without a hard total-risk cap — explain why if asked (strategies.md anti-patterns).

## Output
- Code: file path heading + only changed functions for edits; whole file only when newly generated by the script.
- After code: compile in MetaEditor (F7), then Strategy Tester with "Every tick based on real ticks", then `analyze_trades.py`.
- Always state: backtests do not guarantee future results; validate out-of-sample and on demo before live money. Not financial advice.
